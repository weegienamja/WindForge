# Engineering knowledge service

The production Next.js app speaks to a named Cloudflare Worker through a service binding. Only the authenticated outbound WebSocket can reach the Hetzner process; there is no public SQL or HTTP listener on the server. The relay does not persist queries. PostgreSQL 16 stores revisions, source records, model JSON, component relationships, document vectors and private work. Three fixed operations retrieve public evidence: catalogue, scoped search, and status. No SQL, shell, inference URL or ingestion job is accepted from a browser. Schema descriptions are explanatory definitions, not evidence of a physical subassembly.

## Run and operate

On Ubuntu 24.04, install postgresql-16, postgresql-16-pgvector, python3-psycopg2, python3-numpy, python3-websockets, python3-yaml, python3-venv, curl and gnupg. The application runs as the system user windforge and uses local peer authentication. Install the contents of this directory under /opt/windforge, with the service code owned by root. Create a system-site-packages venv there, install runtime-requirements.txt, and place the two model files below in /opt/windforge/model. Configure only localhost in PostgreSQL. provision.sh checks that setting, installs the migration, creates a non-superuser runtime role, imports the versioned data and starts the service. Never grant that role BYPASSRLS or table ownership.

Semantic search uses the Apache-2.0 [Xenova ONNX conversion of all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2/tree/751bff37182d3f1213fa05d7196b954e230abad9). Pin tokenizer.json (SHA-256 da0e79933b9ed51798a3ae27893d3c5fa4a201126cef75586296df9b4d2c62a0) and onnx/model_quantized.onnx (afdb6f1a0e45b715d0bb9b11772f032c399babd23bfc31fed1c170afc848bdb1). Store the latter as model_quantized.onnx. CPU inference uses one thread, 256 token truncation, mean pooling and vector normalisation. PostgreSQL combines cosine similarity with English full-text rank *within the requested scope*. A retrieved passage is not itself an answer. The app's optional OpenAI-compatible question suggestion ranker accepts a server-configured HTTPS chat-completions URL, model and token in WF_INFERENCE_URL, WF_INFERENCE_MODEL and WF_INFERENCE_TOKEN. By default it can only rank public question suggestions. A user can explicitly allow an unanswered question to be sent for classification into one of a few read-only intents. Only its allowlisted intent is accepted; the server supplies any answer. Private attachments, site results and tool execution never go to the provider. Without a configured service, the local CPU encoder also ranks related structured fields, which are labelled as candidates.

Deploy engineering/relay/wrangler.jsonc using the demo's pinned Wrangler. Set WF_KEY on the relay to the key from the protected host environment file. Keep WF_HANDOFF on the main Worker: this HMAC lets the analyser hand its actual, unmodified provider snapshot to the workspace. The workflow can fetch a fresh site if no signed handoff exists. Status: GET /api/engineering?status on the main site, systemctl status windforge-knowledge, journalctl -u windforge-knowledge, and the ingestion table. Relay and model failure never change the existing point analyser's scientific result. The application makes no control-system connections.

## Sources and refresh

The source library reads public passages for the chosen release. Blade sections use the airfoil coordinates and native chord, twist and relative-thickness grids from each turbine definition. Ingestion writes a content-addressed file per blade under `engineering/geometry/`. Transfer that directory with the catalogue, apply `003.sql`, then run the usual loader. The loader verifies each file's digest before switching the active release. Older investigations keep their original revision.

The catalogue is a derived, content-addressed artefact. The pinned upstream URLs, checksums, reuse terms, field paths, performance tab/column names and the source design version are in catalogue.json. Redistributed IEA, windIO and OpenFAST derivatives keep their upstream Apache notices under licenses/. GRC entries are original factual annotations and links to the research publication or dataset landing page. No GRC drawings, proprietary repair material or raw vibration archives are mirrored. The benchmarking dataset's [additional terms](https://data.openei.org/files/738/WindTurbineConditionMonitoringLicenseInfo.txt) explicitly forbid direct sharing of the datasets. Use the upstream download route. Periodically review those links and interpretations as well as code repository revisions.

Run python engineering/ingest.py in a development environment with PyYAML. Review the generated diff; changes to source availability, units, sheet names or validation must be resolved before publication. The 22 MW WISDEM electricity and thrust curves cover the operating interval; the separate OpenFAST run has no 25 m/s case. Never fill that point or label WISDEM data as OpenFAST. Direct-drive ratio placeholders and empty shaft objects do not imply installed gearboxes. The 3.4 MW identifier is nominal: the assembly rates it at 3,370 kW.

For release, copy the reviewed catalogue to the host and run /opt/windforge/venv/bin/python load.py catalogue.json as the postgres OS user from /opt/windforge. Deduplication, foreign keys, vector construction and the active pointer share one transaction. Previously loaded releases and private report snapshots remain intact. A failed import records the failure separately. Re-running a previous reviewed catalogue switches back without rebuilding embeddings. refresh.py --check records upstream HEAD changes for review, without changing the active release. For a full extraction on a build host, run refresh.py as a maintenance identity with database and staging-directory write access. Never grant the network-facing daemon ingestion permissions.

## Private work and backups

Each browser gets an unguessable Secure, HttpOnly, SameSite=Strict host cookie. The server stores its digest, and the runtime role is subject to forced PostgreSQL row-level security as well as explicit owner predicates. This is a browser capability, not an email account or cross-device login. Clearing the cookie loses access. MCP starts a separate workspace per stdio process. Private uploads are bounded text extracts, kept separate from the public evidence index. Downloaded reports containing attached observations should be treated as private.

The WindForge-only backup timer streams a custom-format pg_dump into GPG public-key encryption before sending it to a dedicated Workers KV namespace. Store **only the encryption public key** as /etc/windforge-backup.asc. Give the relay a separate WF_BACKUP_KEY and configure /etc/windforge-backup-curl.conf mode 0600 with its Authorization header. Install the backup service and timer in this directory. The relay accepts write-only authenticated backup requests; no public read endpoint exists. Daily objects expire after 35 days. The 12 MB encrypted-object guard fails loudly rather than truncating a backup. Plan larger storage before approaching this ceiling; check systemctl --failed, journalctl -u windforge-backup, df -h / and the encrypted object list. Private storage refuses writes below its disk reserve.

Restore with the account's authenticated Wrangler: kv key get daily/YYYY-MM-DD.pgdump.gpg --binding BACKUPS --remote --config engineering/relay/wrangler.jsonc, redirect binary stdout to a private file, decrypt with the offline recovery key and pipe to pg_restore -e into a new database with pgvector installed. Verify counts, source revisions and owner isolation before any cutover. Keep an independent protected copy of the recovery private key; neither the repository nor the Hetzner host contains it. Restore exercises must never overwrite the live database.
